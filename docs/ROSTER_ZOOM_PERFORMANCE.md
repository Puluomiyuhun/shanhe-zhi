# 武将扩充与缩放性能 · 2026-09-24

## 内容与使用入口

- 名录从 11 人扩充到 **89 人**，35 城初始均有至少两名驻留武将；六名动态武将出城后从驻留名单移除。城市侧栏前部展示人物卡，点击进入对应武将详情。
- 城市列表增加驻将数及「驻将名录」入口；武将表支持势力、驻城组合筛选，空结果有明确提示。选择表格行保留滚动位置。
- 接入 **30 张对应人物的官方缩略头像**，共 2,560,616 字节（2.44 MiB），列表、驻城人物和动态武将详情共用。延迟加载、异步解码；没有对应素材的武将保留姓名章。
- 角色沿当前九方势力与区域安排，是混合年代的沙盘编组，**不是历史年份驻军考证**。能力是原型暂定值。驻城名录没有新增地图模型、逐帧模拟或自动出征；动态 AI 仍为六人。

## 优化

1. 地面拾取原本逐次检测整张 819,200 三角面的地形。改为 **100 个带包围盒的拾取分区**，共用原始高精度顶点和相同三角面，仅跳过无关区域。这些代理不加入渲染场景，不增加绘制调用，不降低可见地形精度。
2. 地形悬停限频，滚轮惯性阶段暂缓拾取；点击仍即时精确拾取。归一化滚轮单位并限制单次突增。
3. 远近景保持同一阴影着色器，通过阴影强度渐变代替切换 `castShadow`。静止时复用阴影图；运动或地形压缩变化时按约 80 ms 间隔更新。
4. 名牌使用 CSS `translate` 更新投影，保留原始锚点 transform；移除重复世界矩阵更新。

## 实测与限制

原开发机内置浏览器，1280×720、默认画质。新增「操作说明 → 样区说明与运行状态 → 运行缩放评测」按钮：18 秒固定镜头往返，首 1.5 秒不计帧间隔。仅作同机比较，非最低配置保证。

| 固定缩放测量 | 修改前 / 11 人 | 修改后 / 89 人 |
|---|---:|---:|
| 有效帧数 | 990 | 989 |
| 平均 FPS | 60.0 | 59.9 |
| 帧间隔 P95 | 16.8 ms | 16.8 ms |
| 帧间隔 P99 | 16.8 ms | 16.9 ms |
| 最大帧间隔 | 16.9 ms | 33.3 ms |
| 超过 33.4 ms | 0 | 0 |
| 主循环提交 CPU P95（非 GPU 时间） | 0.6 ms | 1.3 ms |

本机固定缩放并未复现明显掉帧，不能宣称平均帧率提升。已确认的瓶颈是**拾取开销**：Node 在完整地形上测 78 条射线、近远两种高度比例；旧整网格平均 22.557 ms / P95 25.520 ms，新分区平均 0.486 ms / P95 0.912 ms，命中点及格子一致。该微基准不是浏览器输入延迟，也不等同于整个游戏提速 46 倍。

浏览器实际滚轮缩放与右键地面下令验证通过；运行样本约 60 FPS / P95 16.8 ms。曾观测建图约 6.2 秒；没有做跨设备建图时间对照。视觉地形及大规模植被保持原精度，仍有约两百万级三角面；本轮不是全国 LOD 或大规模 AI 优化。30 张 640×480 图片全部解码时理论像素内存约 35 MiB，实际由浏览器加载和回收策略决定。

## 验证

- `verify-roster.mjs`：姓名 / ID 唯一、全部城池覆盖、属性范围、头像文件存在、空筛选、动态人物离城不重复驻留，确认 AI 数仍为六。
- `verify-terrain-picking.mjs`：78 条射线在两种高度比例下与原始网格一致，同时输出微基准。
- `verify-actors.mjs`、`verify-march-motion.mjs`：五分钟 AI 循环、连续运动和暂停等回归通过。
- 浏览器检查头像、城市人物入口、驻城筛选、空结果、实际滚轮与右键下令，未发现控制台错误。
