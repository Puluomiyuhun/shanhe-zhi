## 产品方向与用户偏好

用户喜欢《三国志10、13》的单角色扮演，希望结合《三国志14》式三维大地图：远看宏观疆域，近看地形和六角棋盘。玩家以武将身份行动，长远方向不是默认直接控制全势力。现阶段是个人学习和自用原型。

已明确的偏好：

- 地图要恢弘、有山川层次和清晰的势力地盘；避免土黄糊成一片或过于平面的沙盘。
- UI 偏暗底，金色、少量红色、银色细节；不喜欢黛青主调、过薄宋体、白色武将面板以及过于方正的卡片堆叠。
- 武将列表参考三国志12～14的直观行列：每行一人、能力与身份清楚，配较大的详情头像。
- 点击城市在侧栏更新情报，不为每次选城弹窗。宏观总览、人物名簿等已有独立窗口。
- 拉远城池不能全部消失：可缩成小图标，拥挤时藏文字，悬停再补充。
- 主角驻城时不叠加部队横幅，城市牌仅留「主」；出城后恢复部队模型与旗牌。
- 右键直接下达移动军令并开始推进，不多一步确认；左键查情报。行军路线与目标持续可见，空格快速暂停／继续。
- 希望其他武将真正出征或独自周游，不只是静态名录。

此前农田装饰被用户认为破坏观感；若重新做农田，需要统一比例、材质和地形融合，不要直接加回突兀的规则贴片。用户愿意让 agent 自行做常规设计取舍，先做可玩的改进再验证。

## 已实现的三维版本

| 项目 | 当前事实 |
|---|---|
| 主入口 | `/` 与 `/index.html` 自动进入 `/lab/`；旧版 `/classic.html` |
| 地图 | 104 × 112，即 11,648 个六角格；35 城、9 势力 |
| 势力 | 刘表、袁术、张鲁、曹操、孙坚、马腾、刘焉、董卓、刘繇 |
| 玩家 | 原创沈行舟，襄阳出发，1,200 人先遣队 |
| 移动 | 可达地块寻路、连续插值、到格结算；右键改道；取消、暂停、单步 |
| 地盘与补给 | 玩家经过地块变为己方；从襄阳沿己方可行地块连通供给；后方封锁演练 |
| AI | 文聘、夏侯惇带兵巡防；张勋抵近新野城外观察后返军；徐庶、黄忠、庞德公零兵力周游 |
| 情报 | 城市侧栏、武将动向、势力总览、武将名簿与详情；部分角色交互仍明确标为规划 |
| 存档 | 三维演练无持久化，刷新／重置重新开始；不要误用二维版的存档能力作承诺 |

默认暂停。点击推进或右键下令开始天下演进；没有军令时主角不自行移动。打开情报通常暂停世界，浏览器切后台也暂停。手动「推进一刻」完成主角下一格，并推进 AI 一秒；这仍是演练控制，不是最终统一战役日历。

城市和势力为压缩的混合演练配置，**不是某一历史年份的准确地图**。保留了大致区域意象、通路和视觉布局。旧二维版本的地理数据与三维演练不是同一套坐标，不能直接混用。地形外圈远山属于背景，城池在可玩区域内。

## 尚未实现，不能误报

正式野战／攻城／伤亡、城市归属随战斗改变、全国战略 AI、征募财政、完整外交、真实拜访任务、角色成长官职、三维存档与跨设备同步。名簿中的职责、性格、交互文本和能力数值有不少演示／设计内容。

AI 是有限人数、确定规则的行为循环，不是完整战役对手；张勋城外观察不等于已发生攻城。没有无限刷兵，也没有自动战斗结算。

## 已作出的技术取舍及原因

- 继续使用网页和 Three.js 做验证，无需当前就转原生引擎。现在的流畅表现只验证当前规模，不能外推全国密度和几百支部队。
- 城市使用程序化模型和静态合批；增加城市数量的绘制调用开销较小。
- 地盘染色、名牌、近远景共用同一世界坐标，避免视觉与逻辑分离。
- 活跃军令的路线与左键情报预览独立，查看其他对象不能删除当前路线。
- 主角连续行军在 `march-motion.js`，AI 连续行军在 `actors.js`。两者都按帧时间推进，但尚不是共享一个运动模块。
- 原始地形网格仍很大；下一阶段应先做分块、远近细节和批量寻路调度，再扩全国。

## 有用的故障记忆

| 现象 | 原因与当前处理 |
|---|---|
| 启动后只有老地图 | 根 index 曾是二维版；已改默认跳转三维，旧版移至 classic |
| 旋转时城市横幅抖 | 投影用了旧相机矩阵，悬停还会改变锚点高度；现在先同步矩阵，详情独立定位 |
| 右键弹网页菜单 | 城牌和 UI 覆盖在 canvas 上，canvas 局部拦截不够；现在文档级屏蔽 contextmenu |
| 空格在点击按钮后失灵 | 曾跳过所有 button 焦点；现在接管普通按钮下的空格并阻止原生激活、按键重复 |
| 主角走一格停一下 | 每格成本计时与固定 330 ms 动画不一致；现在连续运动，到格心才结算 |
| 城市侧栏周期性开销 | 曾每 400 ms 重新寻路；现在缓存静态路线和周边地块，换城／玩家位置／世界后失效 |
